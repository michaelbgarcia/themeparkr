# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`themeparkr` is a small R package wrapping the public ThemeParks API (https://api.themeparks.wiki, docs at https://themeparks.wiki/). No auth is required. Install from GitHub with `remotes::install_github("michaelbgarcia/themeparkr")`.

## Commands

Run from the repo root in R (`.Rprofile` activates `renv` automatically):

```r
devtools::document()   # regenerate NAMESPACE and man/*.Rd from roxygen comments
devtools::load_all()   # load package for interactive testing
devtools::check()      # R CMD check (examples hit the live API, so network is required)
devtools::install()
```

There is no `tests/` directory; verification is done by calling the exported functions against the live API.

## Architecture

Each exported function lives in its own file under `R/` and maps 1:1 to an API endpoint:

| Function | Endpoint |
|---|---|
| `tpr_destinations()` | `v1/destinations` |
| `tpr_entity(id)` | `v1/entity/{id}` |
| `tpr_entity_children(park)` | `v1/entity/{id}/children` |
| `tpr_entity_live(id)` | `v1/entity/{id}/live` |

All follow the same pattern: build the URL with `httr::modify_url()` + `glue`, `httr::GET`, `httr::stop_for_status`, parse with `jsonlite::fromJSON(..., simplifyVector = FALSE)`, then flatten the nested list into a tibble with purrr/dplyr/tidyr. Functions return a plain tibble.

Endpoint-specific reshaping worth knowing:
- `tpr_entity` and `tpr_entity_children` unnest the nested `location` field and pivot it into numeric columns (children keeps only `latitude`/`longitude`). `tpr_entity_children` also prepends a `park` column holding the input id.
- `tpr_entity_live` builds the tibble column-by-column with `map_chr`/`map` + `pluck(.default = NA)` so missing fields don't break; `queue`, `forecast`, and `showtimes` stay as list-columns.

## Conventions

- `NAMESPACE` and `man/` are generated by roxygen2 — edit the roxygen `@importFrom`/`@export` tags in `R/*.R` and run `devtools::document()`, never edit them by hand. Any new package dependency must also be added to `Imports:` in `DESCRIPTION`.
- Code uses `=` for assignment and `pkg::fn()` qualified calls.
- Bump `Version:` in `DESCRIPTION` when changing output shape.
- `R/zzz.R` defines `print.themeparks_api`, a leftover from an earlier design where functions returned a `themeparks_api` S3 object (`content`/`path`/`response`); current functions don't use it.
- `inst/scratch/scripts.R` is an excluded (`.Rbuildignore`) prototyping scratchpad, not package code.
