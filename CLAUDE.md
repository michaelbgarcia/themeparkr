# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`themeparkr` is a small R package wrapping the public ThemeParks API (https://api.themeparks.wiki, docs at https://themeparks.wiki/). No auth is required. Install from GitHub with `remotes::install_github("michaelbgarcia/themeparkr")`.

## Commands

Run from the repo root in R (`.Rprofile` activates `renv` automatically):

```r
devtools::document()   # regenerate NAMESPACE and man/*.Rd from roxygen comments
devtools::load_all()   # load package for interactive testing
devtools::test()       # offline tests against recorded API responses
devtools::test(filter = "tpr_entity_children")  # single test file
devtools::check()      # R CMD check; examples are @examplesIf interactive(), so no network needed
devtools::install()
```

Tests never hit the network: `local_fixture("name")` (in `tests/testthat/helper-fixtures.R`) mocks `tpr_fetch()` to return `tests/testthat/fixtures/name.json`. Tests of `tpr_fetch()` itself use `httr2::local_mocked_responses()`. To cover a new API shape, save a trimmed real response there with `curl`.

## Architecture

Each exported function lives in its own file under `R/` and maps 1:1 to an API endpoint:

| Function | Endpoint |
|---|---|
| `tpr_destinations()` | `v1/destinations` |
| `tpr_entity(id)` | `v1/entity/{id}` |
| `tpr_entity_children(park)` | `v1/entity/{id}/children` |
| `tpr_entity_live(id)` | `v1/entity/{id}/live` |

All follow the same pattern: build the path with `glue`, call the internal `tpr_fetch(path, task)` (`R/utils-fetch.R`: httr2 request with user agent, timeout and retry; HTTP errors become a `themeparkr_http_error` via `cli::cli_abort()` reported against the calling exported function; body parsed with `jsonlite::fromJSON(..., simplifyVector = FALSE)`), then flatten the nested list into a tibble with purrr/dplyr/tidyr. Functions return a plain tibble.

Endpoint-specific reshaping worth knowing:
- `tpr_entity` and `tpr_entity_children` replace the nested `location` field with numeric `latitude`, `longitude` columns via `tpr_location()` (`R/utils-location.R`); the API sometimes omits `location` or sends null coordinates, which become `NA`. `tpr_entity_children` also prepends a `park` column holding the input id, and returns a typed 0-row tibble for leaf entities.
- `tpr_entity_live` builds the tibble column-by-column with `map_chr`/`map` + `pluck(.default = NA)` so missing fields don't break; `queue`, `forecast`, and `showtimes` stay as list-columns.

## Conventions

- `NAMESPACE` and `man/` are generated by roxygen2 — edit the roxygen `@importFrom`/`@export` tags in `R/*.R` and run `devtools::document()`, never edit them by hand. Any new package dependency must also be added to `Imports:` in `DESCRIPTION`.
- Code uses `=` for assignment and `pkg::fn()` qualified calls; the only `@importFrom` is magrittr's `%>%` (`R/utils-pipe.R`).
- Bump `Version:` in `DESCRIPTION` when changing output shape.
- `inst/scratch/scripts.R` is an excluded (`.Rbuildignore`) prototyping scratchpad, not package code.
